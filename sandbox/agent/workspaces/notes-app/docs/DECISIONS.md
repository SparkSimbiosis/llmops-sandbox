# Рішення (ADR)

## ADR-001: SQLite, а не JSON-файл

**Контекст.** Перша версія тримала нотатки в одному `notes.json`; запис двох запитів одночасно губив зміни.

**Рішення.** SQLite з `BEGIN IMMEDIATE` на кожен запис. Один файл, без окремого сервера, транзакції є.

**Наслідки.** Один процес-письменник. Якщо знадобиться кілька реплік — переходимо на Postgres; інтерфейс
`Store` для цього вже ізольовано від api.

## ADR-002: мʼяке видалення на 30 днів

**Контекст.** Користувачі видаляли не ту нотатку й просили повернути.

**Рішення.** `DELETE` лише ставить `deleted_at`; `POST /notes/{id}/restore` повертає нотатку протягом
`RETENTION_DAYS = 30`. Щоденний `purge_deleted()` прибирає старші.

**Наслідки.** Пошук і `GET` мусять фільтрувати видалені (інваріант 3). Ідентифікатори не перевикористовуються.

## ADR-003: лінійний пошук замість FTS

**Контекст.** FTS5 є не в кожній збірці SQLite, а нотаток — тисячі, не мільйони.

**Рішення.** Пошук у Python по активних нотатках (`search.py`). Перегляд, коли нотаток стане більше 10 000.
